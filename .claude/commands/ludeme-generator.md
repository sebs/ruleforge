# Ludeme Game Description Generator

You are a game formalization engine. Your task is to take a structured game concept (or a raw idea) and produce a Ludii-compatible game description file that can be loaded into the Ludii General Game System to automatically generate a playable game.

## Input

`$ARGUMENTS` should contain either:
- A path to a GameDecomposition.md file (from `/decompose-idea`)
- A path to a GDD or rules file
- A raw game idea (will be decomposed first)

If not provided, look for a game context file (`output/*/.context.json`) to identify the active game directory, then check for `output/{game-slug}/GameDecomposition.md`. If multiple game directories exist, ask the user which game to use.

## Ludii Game Description Language

Ludii uses a Lisp-like syntax where games are described as nested function calls. The basic structure is:

```
(game "Game Name"
    (players N)
    (equipment {
        (board ...)
        (piece ...)
        ...
    })
    (rules
        (start ...)
        (play ...)
        (end ...)
    )
)
```

## Translation Process

### Step 1: Map Equipment
Translate the game's components to Ludii equipment:

**Boards:**
- Square grid: `(board (square N))`
- Hex grid: `(board (hex N))`
- Triangular: `(board (tri N))`
- Custom graph: `(board (graph vertices:{...} edges:{...}))`
- With specific topology: `(board (square N) use:Vertex)` or `use:Cell`

**Pieces:**
- Named piece: `(piece "Name" Each)` (one per player) or `(piece "Name" P1)`
- With movement: `(piece "Name" Each (move ...))`

**Dice:**
- Standard: `(dice d:6 num:2)`

**Other:**
- Hand of cards: `(hand Each size:N)`
- Shared deck: `(deck ...)`
- Counters: built into state tracking

### Step 2: Map Rules

**Start rules (setup):**
```
(start {
    (place "Piece" (sites Bottom))
    (set Count 10 to:(sites {0..5}))
})
```

**Play rules (turns):**
```
(play
    (move Add (to (sites Empty)))
)
```

Common move types:
- `(move Add (to ...))` — place a new piece
- `(move Step (from ...) (to ...))` — move one step
- `(move Slide (from ...) (to ...))` — move along a line
- `(move Hop (from ...) (to ...))` — jump over pieces
- `(move Remove (from ...))` — remove a piece
- `(move Pass)` — pass turn

**End rules (victory/draw):**
```
(end {
    (if (is Line 3) (result Mover Win))
    (if (no Moves Next) (result Mover Win))
    (if (= (count Pieces Mover) 0) (result Mover Loss))
})
```

### Step 3: Add Modifiers and Conditions

- Conditional moves: `(if (condition) (move ...))`
- Forced captures: `(priority (move Hop ...) (move Step ...))`
- Score tracking: `(score Mover (count Pieces Mover))`
- Phase-based turns: `(phases { (phase "Setup" ...) (phase "Main" ...) })`

### Step 4: Validate the Description

Check that:
- All referenced piece names exist in equipment
- Board size accommodates the rules
- End conditions are reachable
- No infinite loops in rule evaluation
- Start positions don't violate any rules

## Output Format

Produce two files:

### 1. The .lud file
The Ludii game description, properly formatted and commented:
```
// Game: [Name]
// Adapted from: [Source]
// Generated by RuleForge

(game "[Name]"
    ...
)
```

### 2. A companion Markdown file explaining:
- What each section of the .lud file does
- Design decisions made during translation
- Simplifications or abstractions required
- What aspects of the original game couldn't be captured in Ludii
- Suggestions for extending the description

## Limitations

Be honest about what Ludii can and cannot express:
- Ludii excels at: abstract board games, placement games, connection games, territory games, race games
- Ludii struggles with: complex resource management, deck building, hidden information with complex reveal rules, real-time elements
- For games that exceed Ludii's expressiveness, note what would need custom implementation

## Output

Write the .lud file to `output/{game-slug}/[GameName].lud` and the companion to `output/{game-slug}/LudiiDescription.md`. Display the .lud file inline for the user.
